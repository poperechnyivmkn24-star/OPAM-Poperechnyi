# Лабораторна 9 · Сортування

Сортування вставками стабільне й робить n−1 порівнянь без записів на відсортованому масиві. Швидке сортування бере медіану трьох і окремо групує елементи, що дорівнюють опорному. Це виключає однакові ключі з наступних викликів, але обміни можуть змінити порядок рівних елементів. У Results.md наведені трасування, заміри, експеримент зі стабільністю та фактичне відношення кількості порівнянь на 10 000 числах. Лекційне 376 базується на іншому розподілі та оцінках. Тут вставки залежать від кількості інверсій, а швидке сортування отримує перевагу від лише 61 можливого ключа.

Спеціалізований Array.Sort для цілих чисел може уникати частини викликів переданого делегата та використовує гібридне сортування з окремою обробкою малих ділянок. На відміну від власних реалізацій, еталон не збільшує лічильники під час порівнянь і записів. Для 100 000 записів із ключами 0–300 я б вибрав стабільне сортування підрахунком. Воно будує 301 лічильник, обчислює позиції й за один прохід розміщує записи зі збереженням порядку однакових ключів.

У досліді із двома ключами обидві реалізації застосовують стабільне злиття. Під час двох проходів сортування за балом іде першим, за групою — останнім. Для замірів цього досліду використовуються записи студентів, для вставок, швидкого та Array.Sort — цілі числа.


Василь Поперечний, КН-3/1. Для запуску в папці лабораторної виконайте `dotnet run -c Release` з .NET 10 SDK.
