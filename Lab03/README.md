# Лабораторна 3 · Рекурсивні алгоритми

Василь Поперечний. Для запуску виконайте `dotnet run -c Release` з .NET 10 SDK і введіть шлях до каталогу.

- `Scan` рахує файли .cs та їхній розмір. У каталозі без підкаталогів рекурсивні виклики відсутні. Каталоги без доступу та посилання на каталоги пропускаються.
- `Solve` повертає 0 для порожнього відрізка. Для одного елемента повертає 1, якщо елемент більший за 3, і 0 в іншому випадку.
- `Change` завершує гілку після розгляду всіх номіналів і зараховує спосіб лише за нульового залишку. Для 11 грн отримано 11 способів.
- `CountLoop` на тому самому масиві повернув 6, як і `Solve`. Максимальна глибина від кореня дорівнювала 4.

## Трасування

    enter Solve(0..3)
      enter Solve(0..1)
        enter Solve(0..0)
        exit  Solve(0..0) -> 1
        enter Solve(1..1)
        exit  Solve(1..1) -> 0
      exit  Solve(0..1) -> 1
      enter Solve(2..3)
        enter Solve(2..2)
        exit  Solve(2..2) -> 1
        enter Solve(3..3)
        exit  Solve(3..3) -> 1
      exit  Solve(2..3) -> 2
    exit  Solve(0..3) -> 3

Вкладений виклик повертає значення перед тим, як продовжиться його батьківський виклик. Тому всередині однієї гілки виходи йдуть від найглибшого рівня до кореня.

Для підрахунку в масиві достатньо лічильника в одному циклі. Поділ навпіл зберігає ту саму лінійну кількість відвідувань елементів і потребує додаткових кадрів виклику. Для обходу дерева каталогів ітеративній версії потрібен власний стек шляхів до ще не опрацьованих підкаталогів. Рекурсивна версія зберігає стан обходу в кадрах виклику.
