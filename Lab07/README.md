Лямбда зчитує поріг із захопленої змінної під час виклику. Тому після зміни з 3 на 1000 перевірка для 4 повернула False. Лямбди з for поділяють одну змінну, тож усі побачили підсумкове 3. У foreach кожна ітерація має власну змінну, тож отримано 0, 1, 2. Для for це виправляється копіюванням лічильника в нову локальну змінну на кожній ітерації.

Три використані поєднання типу й критерію вимагали б трьох окремих функцій із вбудованими умовами. Тут достатньо одного Filter з трьома переданими предикатами. Для №1 перевірка дати працює з правилами календаря та цілими числами, тому узагальнений тип не додав би повторного використання.
